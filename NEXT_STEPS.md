# ПЛАН ДАЛЬНЕЙШИХ ДЕЙСТВИЙ И РЕКОМЕНДАЦИИ ДЛЯ CHATGPT

В данном документе сформулирован структурированный список открытых задач, список дефектов и дорожная карта дальнейшей разработки.

## 1. РЕЕСТР ВЫЯВЛЕННЫХ ДЕФЕКТОВ И ПРОБЛЕМ

| ID | Компонент | Описание дефекта | Серьёзность |
|---|---|---|---|
| **DEF-01** | Инфраструктура флешки | USB-накопитель `E:\` физически извлечён из ПК мастера. Файлы готовы в `C:\Users\Lolo\Documents\Veyon_Flash`, но ещё не скопированы на физическую флешку. | **Высокая (P0)** |
| **DEF-02** | Безопасность `server.py` | Эндпоинт `/files/` отдаёт закрытый ключ `admin_private_key.pem` без пароля любому клиенту подсети. | **Средняя (P1)** |
| **DEF-03** | CI/CD Veyon C++ | Сборка в GitHub Actions компилирует только `usersessioncontrol.dll` и пропускает `windows-platform.dll`. Изменения в `WindowsUserFunctions.cpp` не доставляются. | **Средняя (P2)** |
| **DEF-04** | Дистрибуция C++ плагина | Клиентские компьютеры устанавливаются из чистого установщика `veyon-setup.exe` и не получают модифицированные DLL. | **Средняя (P2)** |

## 2. ПОШАГОВЫЙ ПЛАН РАБОТЫ ДЛЯ CHATGPT

### ЭТАП 1: Первичное развертывание и физическая синхронизация (P0)
1. **Проверить подключение накопителя:**
   ```powershell
   if (Test-Path "E:\") {
       Copy-Item "C:\Users\Lolo\Documents\Veyon_Flash\*" "E:\" -Recurse -Force
       Write-Host "Флешка E: успешно обновлена!" -ForegroundColor Green
   } else {
       Write-Host "Флешка E: не найдена. Подключите диск E: к ПК." -ForegroundColor Yellow
   }
   ```
2. **Убедиться в чистоте корня флешки:**
   В корне `E:\` должен находиться **строго один файл `VEYON.bat`** и папка `data\`.

---

### ЭТАП 2: Тестирование на одном ПК ученика в классе (P1)
1. Вставить флешку в один тестовый компьютер ученика (например, `PC-1`).
2. Запустить `VEYON.bat` от имени Администратора $\rightarrow$ выбрать пункт `[1]`.
3. Дождаться сообщения об успешной настройке:
   * Проверить, что пользователь переименован в `Student`.
   * Проверить, что в реестре прописан `ForceAutoLogon = 1` и пароль `[REDACTED_PASSWORD]`.
4. Перезагрузить компьютер:
   * **Ожидаемое поведение:** ПК загружается, заставка блокировки не появляется, Windows автоматически входит на рабочий стол пользователя `Student` без нажатия клавиш.
5. На ПК преподавателя запустить «Veyon Master» и проверить, что экран `PC-1` транслируется.

---

### ЭТАП 3: Устранение уязвимости в `server.py` (P1)
В файле `data/server.py` ограничить раздачу файлов через `/files/`:
```python
# Белый список для раздачи
ALLOWED_PUBLIC_FILES = {"veyon-setup.exe", "admin_public_key.pem", "setup_student.ps1"}
if filename not in ALLOWED_PUBLIC_FILES:
    self.send_response(403)
    self.end_headers()
    return
```

---

### ЭТАП 4 (Опциональный): Доработка C++ кнопки «Вход» в GUI Veyon Master (P2)
Если преподаватель обязательно потребует, чтобы вход происходил не только системно при включении, но и по нажатию кнопки в окне Veyon Master:
1. Отредактировать `.github/workflows/build-windows.yml`:
   * В секцию `ninja` добавить цель `windows-platform`:
     ```bash
     ninja usersessioncontrol windows-platform
     ```
   * Добавить шаг бинарного патча Qt-метаданных для обеих библиотек.
   * Опубликовать обе DLL в артефактах GitHub Actions.
2. В скрипте `setup_student.ps1` после тихой инсталляции `veyon-setup.exe /S` добавить автоматическую подмену библиотек в папке `C:\Program Files\Veyon\plugins\`:
   ```powershell
   Copy-Item "$dataDir\usersessioncontrol.dll" "$installDir\plugins\" -Force
   Copy-Item "$dataDir\windows-platform.dll" "$installDir\plugins\" -Force
   ```
