# ПЛАН ДАЛЬНЕЙШИХ ДЕЙСТВИЙ И РЕКОМЕНДАЦИИ ПО ДОРАБОТКЕ

В данном документе описаны конкретные действия, которые необходимо выполнить пользователю на реальном оборудовании, а также архитектурный анализ направления C++.

---

## 1. Действия пользователя на реальном оборудовании

### Шаг 1. Копирование на физический USB-накопитель
На момент подготовки данного комплекта диск `E:\` физически отключён.  
Когда флешка будет вставлена в компьютер:
1. Откройте PowerShell и выполните синхронизацию:
   ```powershell
   Copy-Item "C:\Users\Lolo\Documents\Veyon_Flash\*" "E:\" -Recurse -Force
   ```
2. Убедитесь, что в корне флешки находится только `VEYON.bat` и папка `data\`.

### Шаг 2. Безопасное тестирование на одном компьютере ученика
1. Выберите один тестовый компьютер в классе (например, `PC-1`).
2. Вставьте флешку $\rightarrow$ запустите `VEYON.bat` от имени Администратора.
3. Выберите пункт **`[1] НАСТРОИТЬ ЭТОТ КОМПЬЮТЕР КАК ПК УЧЕНИКА`**.
4. Дождитесь зелёного сообщения о завершении настройки.
5. Перезагрузите компьютер ученика:
   * **Проверка:** Компьютер должен без задержек и без экрана с часами войти на рабочий стол пользователя `Student`.
6. На ПК учителя откройте **Veyon Master** и убедитесь, что экран `PC-1` появился в списке активных мониторов.

## 2. Архитектурный анализ и доработка C++ ядра Veyon (Подсистема C)

### Анализ текущей реализации:
В форке `anonimname163/veyon` были изменены:
* `plugins/usersessioncontrol/UserSessionControlPlugin.cpp`
* `plugins/platform/windows/WindowsUserFunctions.cpp`

### Выявленные фундаментальные ограничения:
1. **Несоответствие версий Veyon:** Исходный код форка синхронизирован с базовым коммитом Veyon **4.9.6** (`1cebf45f6`). Однако фактически установленный установщик на компьютерах — **4.11.3**. Разница в мажорно-минорных версиях влечёт несовместимость ABI ядра Veyon Core и загрузчика плагинов.
2. **Ограничения Windows 10/11 Secure Desktop:**
   * Попытка симуляции нажатий клавиш (`OpenInputDesktop`, `keybd_event`, `SendInput`) из контекста системной службы (Session 0) в сессию Winlogon блокируется современными механизмами безопасности UIPI и XAML Credential Provider.
   * Экран блокировки Windows 10/11 не имеет отдельного текстового поля для ввода имени пользователя, а курсор сфокусирован на поле пароля уже выбранного аватара.
3. **Почему системный `ForceAutoLogon` превосходит симуляцию ввода:**
   * Механизм `Winlogon\ForceAutoLogon = 1`, реализованный в `setup_student.ps1`, работает на уровне ядра Windows LSA (Local Security Authority).
   * Он срабатывает на 100% надёжно при любом включении компьютера, перезагрузке или вызове сброса сессии (`logoff.exe`), не завися от анимаций экрана, задержек (`Sleep`) и языка раскладки клавиатуры.

### Рекомендации, если потребуется довести до конца C++ плагин:
1. **Синхронизировать форк с веткой `4.11`:** Перебазировать изменения с коммита `1cebf45f6` на тег `v4.11.3`.
2. **Собрать обе библиотеки в GitHub Actions:**
   В файле `.github/workflows/build-windows.yml` изменить команду сборки:
   ```bash
   ninja usersessioncontrol windows-platform
   ```
3. **Заменить DLL в дистрибутиве:** Упаковать скомпилированные `.dll` в каталог `data\` и добавить их подмену в `setup_student.ps1` после инсталляции.
