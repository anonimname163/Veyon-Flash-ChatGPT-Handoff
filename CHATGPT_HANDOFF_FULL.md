## 1. ВВЕДЕНИЕ И ЦЕЛИ ПРОЕКТА

### 1.1. Назначение системы
Проект предназначен для комплексной автоматизации жизненного цикла компьютерного класса информатики («Информатика-1»):
* 13–15 рабочих мест учащихся (`PC-1` .. `PC-12`, `main-pc`);
* 1 рабочее место преподавателя (учитель/мастер `Lolo`).

### 1.2. Решаемые проблемы
1. **Трудоёмкость ручной настройки:** Исключение необходимости вручную устанавливать софт, настраивать брандмауэр, генерировать и копировать ключи доступа на каждый отдельный компьютер.
2. **Зависание экрана блокировки Windows 10/11:** На стандартном экране входа Windows отображается заставка с часами (шторка экрана блокировки), поглощающая любые программные нажатия клавиш сторонних сервисов.
3. **Сбой имитации клавиатурного ввода штатного Veyon:**
   * На русскоязычных ОС экран входа по умолчанию имеет русскую раскладку (`00000419`), из-за чего латинские пароли вводятся неверно.
   * На экране входа Windows 10/11 уже выбран локальный пользователь и фокус ввода находится в поле ввода пароля. Стандартный Veyon посылал нажатия `Delete` $\rightarrow$ `Имя` $\rightarrow$ `Tab` $\rightarrow$ `Пароль`, что приводило к вводу имени в поле пароля и смещению курсора по `Tab`.
   * Функция `prepareLogon()` штатного Veyon не вызывала `performLogon()`, если в системе никто не был авторизован, ожидая перезапуска сессии через `logoff()`.
4. **Ненадёжность стороннего софта:** Необходимость иметь гарантированный 100% вход учащихся в систему без сбоев.

## 2. АРХИТЕКТУРА И РАЗДЕЛЕНИЕ ТРЕХ ПОДСИСТЕМ

В проекте строго разграничены **три независимые подсистемы**, которые решают разные задачи:

```
┌────────────────────────────────────────────────────────────────────────────────────────┐
│                                   АРХИТЕКТУРА СИСТЕМЫ                                  │
├──────────────────────────────┬─────────────────────────────┬───────────────────────────┤
│ ПОДСИСТЕМА A                 │ ПОДСИСТЕМА B                │ ПОДСИСТЕМА C              │
│ Первичное развертывание      │ Повседневное управление     │ Модификации ядра Veyon    │
│ (Flash-накопитель E:\)       │ (Veyon Master GUI)          │ (C++ Fork в veyon.git)    │
├──────────────────────────────┼─────────────────────────────┼───────────────────────────┤
│ • VEYON.bat (корень флешки)  │ • Veyon Master на ПК учителя│ • UserSessionControlPlugin│
│ • data\setup_student.ps1/.bat│ • Мониторинг экранов учеников│ • WindowsUserFunctions    │
│ • data\setup_master.ps1/.bat │ • Демонстрация экрана       │ • GitHub Actions CI/CD    │
│ • data\server.py (Веб-панель)│ • Блокировка ввода          │ • Цель: сделать рабочим   │
│   (ТОЛЬКО для инсталляции!)  │ • Завершение работы         │   вход по кнопке «Логин»  │
│ • ForceAutoLogon реестра     │ • Отправка файлов           │   в Veyon Master без окон │
└──────────────────────────────┴─────────────────────────────┴───────────────────────────┘
```

### Принципиальные границы:
1. **Веб-панель (`server.py`)** — это **утилита первичной инсталляции**, а НЕ замена Veyon Master! Она нужна во время обхода компьютеров: видеть, кто уже появился в сети, протестировать пакеты Wake-on-LAN и отдать однострочник сетевой установки `irm http://.../setup | iex`.
2. **Повседневное управление уроком** ведётся **исключительно через официальный Veyon Master**.
3. **Автоматический вход после перезагрузки** обеспечивается нативным системным механизмом `Winlogon\ForceAutoLogon = 1`, не зависящим от службы Veyon.
4. **Изменения в C++ коде Veyon** разрабатывались для починки кнопки «Вход» внутри самого интерфейса Veyon Master, но на данный момент **не развёрнуты на клиентских ПК**.

## 3. ПОЛНАЯ ХРОНОЛОГИЯ РАЗРАБОТКИ

### Этап 1. Исходная проблема со стандартным Veyon
Пользователь обратился с жалобой: при попытке войти на ПК учеников через кнопку «Логин» в Veyon Master:
* либо на клиентах ничего не происходит, пока физически не тронешь мышь или не подключишься по VNC;
* либо Windows пишет «Неверный пароль» из-за русской раскладки или смещения фокуса ввода.

### Этап 2. Эксперименты с модификацией исходного кода Veyon C++
1. Создан форк `https://github.com/anonimname163/veyon.git` на базе коммита `1cebf45f6` (Veyon 4.9.6).
2. В плагине `UserSessionControlPlugin.cpp` убран вызов модального окна `UserLoginDialog`. Логин и пароль берутся из настроек `QSettings`.
3. Добавлена новая фича `m_setPasswordFeature` для удалённой установки пароля через `net user`.
4. На стороне клиента добавлен вызов `OpenInputDesktop()`, сброс заставки клавишами `VK_SPACE`/`VK_RETURN`, сброс раскладки через `LoadKeyboardLayoutW("00000409")` и посимвольный ввод через `KEYEVENTF_UNICODE`.
5. В `WindowsUserFunctions.cpp` исправлен вызов `prepareLogon()`: если сессия пуста, немедленно вызывается `performLogon()` без ожидания рестарта сервера. В `performLogon()` убран ввод имени пользователя, добавлен сброс шторки и принудительное переключение раскладки.
6. Настроен GitHub Actions workflow `.github/workflows/build-windows.yml` с использованием MinGW-w64 и Qt 6.11 (с бинарным патчем метаданных до 6.10).

### Этап 3. Проблема накопления мусора и конфликт скриптов
В процессе отладки на диске `E:\` и в проекте появилось множество разрозненных `.bat` и `.ps1` файлов:
* скрипты с разной логикой авторизации;
* сбои кодировок Windows-1251 vs UTF-8 в PowerShell 5.1;
* несовпадение синтаксиса `veyon-cli auth-keys` vs `veyon-cli authkeys`;
* на машинах учеников продолжала работать стандартная сборка из `veyon-setup.exe`, так как скомпилированная DLL копировалась вручную только на ПК учителя.

### Этап 4. Переписывание с чистого листа (Clean Slate Rewrite)
Пользователь выдал категорическое требование:
> *«так он все ещё не работает давай сделаем так ты полностью удалиш все старые данные и напишеш все с нуля запрешено пользоваться старыми данными»*

Все старые временные файлы и скрипты были удалены. Сохранены только базовые эталонные бинарники и ключи:
- `veyon-setup.exe` (чистый инсталлятор 4.9.6);
- `admin_private_key.pem` и `admin_public_key.pem`;
- `computers_list.txt`.

Создана новая монолитная модульная структура:
- В корне флешки — строго один файл `VEYON.bat` с самоэлевацией прав;
- Все компоненты убраны в подкаталог `data/`;
- Скрипт `setup_student.ps1` переписан на системный Windows `ForceAutoLogon = 1`, что гарантирует 100% надёжность автовхода на уровне ядра ОС;
- Скрипты сохранены в `UTF-8 with BOM` для гарантированной работы в PowerShell 5.1.

## 4. ДЕТАЛЬНЫЙ АНАЛИЗ ДВУХ МОДИФИКАЦИЙ В ИСХОДНОМ КОДЕ VEYON

### 4.1. Модификация 1: `plugins/usersessioncontrol/UserSessionControlPlugin.cpp`
* **Файл:** `plugins/usersessioncontrol/UserSessionControlPlugin.cpp` (+ `.h`, `CMakeLists.txt`)
* **Коммиты:** `14dce3bc2`, `50a745ac6`, `26ecdd260`, `165cf11e2`
* **Что изменено:**
  1. *На стороне Master:* В функции `startFeature()` для `m_userLoginFeature` удалён модальный диалог `UserLoginDialog`. Логин и пароль читаются из `QSettings("Veyon", "VeyonMaster")`. Добавлена фича `m_setPasswordFeature` ("Задать пароль пользователя"), позволяющая учителю задать новый пароль для учеников через GUI и сохранить его в настройки.
  2. *На стороне Client:* В `handleFeatureMessage()`:
     - Для `m_setPasswordFeature`: вызов `net user <username> <plainPassword>`. Если пользователя нет, выполняется `/add` и добавление в группу «Пользователи»/«Users».
     - Для `m_userLoginFeature`: вызов `reg add` для параметров автологина и раскладки `00000409`, после чего создаётся отдельный поток `std::thread`, вызывающий `OpenInputDesktop(0, FALSE, GENERIC_WRITE)`, `SetThreadDesktop()`, пробуждение пробелом, смену раскладки через `LoadKeyboardLayoutW` и `WM_INPUTLANGCHANGEREQUEST`, эмуляцию `Ctrl+A` $\rightarrow$ `BackSpace`, посимвольную отправку пароля через `KEYEVENTF_UNICODE` и нажатие `Return`.
* **Почему НЕ работает:**
  1. **Скомпилированная DLL не была развернута на ученических ПК.** Сборка происходила в GitHub Actions, артефакт `usersessioncontrol.dll` тестировался вручную только на компьютере преподавателя. Ученики устанавливались из стандартного установщика `veyon-setup.exe` 4.9.6!
  2. **Ограничения безопасности Secure Desktop (Session 0 Isolation):** В современных версиях Windows 10/11 служба SYSTEM изолирована от рабочего стола Winlogon. Даже при успешном вызове `OpenInputDesktop()` компонент `LogonUI.exe` (XAML Credential Provider) часто игнорирует события `SendInput` или сбрасывает фокус ввода.
  3. **Тайминги экрана:** Задержка `Sleep(400)` недостаточна для выхода монитора из сна и завершения анимации поднятия заставки.

### 4.2. Модификация 2: `plugins/platform/windows/WindowsUserFunctions.cpp`
* **Файл:** `plugins/platform/windows/WindowsUserFunctions.cpp`
* **Коммит:** `165cf11e2`
* **Что изменено:**
  1. В `prepareLogon()`:
     - В апстриме: если `!isAnyUserLoggedOn()`, вызывался `logoff()`, возвращался `true`, и сервис ждал сигнала `applicationLoaded`. При пустой сессии `logoff()` ничего не делал, сигнал не приходил, вход не выполнялся.
     - В форке: если пользователь уже есть в сессии — вызывается `logoff()`. Если никого нет (`!isAnyUserLoggedOn()`) — немедленно вызывается `performLogon(username, password)`.
  2. В `performLogon()`:
     - Убран ввод имени пользователя `sendString(username)` и лишнее нажатие `Tab` (так как курсор уже в поле пароля).
     - Добавлен сброс заставки: `XK_space`, пауза 300мс, `XK_Escape`.
     - Добавлено принудительное переключение раскладки на английский: `Alt_L + Shift_L`.
     - Добавлена очистка поля: `Ctrl + A` $\rightarrow$ `BackSpace`.
     - Печатается только `plainPassword`.
* **Почему НЕ работает:**
  1. **Файл вообще НИКОГДА не компилировался в CI!** В `.github/workflows/build-windows.yml` команда сборки вызывала `ninja usersessioncontrol`. Цель `windows-platform.dll` (или `veyon-core`) не собиралась и не входила в артефакты.
  2. На всех компьютерах (и у учителя, и у учеников) в каталоге `C:\Program Files\Veyon\plugins\` находится **оригинальная немодифицированная библиотека платформы** из официального дистрибутива.

### 5.1. Пошаговая работа `setup_student.ps1`:
1. Проверка прав локального Администратора.
2. Проверка наличия `veyon-cli.exe`. При отсутствии — запуск тихой установки `veyon-setup.exe /S`.
3. Остановка служб и процессов Veyon перед модификацией.
4. Поиск существующей локальной несистемной учётной записи и её переименование в `Student` (для сохранения всех файлов на рабочем столе и документов учеников). Если пользователей нет — создание `Student`.
5. Установка бессрочного пароля `[REDACTED_PASSWORD]`.
6. Запись в реестр `Winlogon`:
   * `AutoAdminLogon = "1"`
   * `ForceAutoLogon = "1"`
   * `DefaultUserName = "Student"`
   * `DefaultPassword = "[REDACTED_PASSWORD]"`
   * `DisableCAD = 1`
7. Отключение экрана заставки: `Policies\Microsoft\Windows\Personalization\NoLockScreen = 1`.
8. Установка английской раскладки по умолчанию на экране входа: `HKEY_USERS\.DEFAULT\Keyboard Layout\Preload\1 = "00000409"`.
9. Импорт открытого ключа `admin/public` через `veyon-cli authkeys import`.
10. Открытие необходимых портов в Windows Firewall (11100, 11200, 11300, 11400 TCP/UDP).
11. Включение параметров Wake-on-LAN на всех физических сетевых адаптерах в реестре (`EnablePME=1`, `WakeOn=6`, `WakeOnMagicPacket=1`).
12. Регистрация текущего IP и MAC-адреса ПК в общем списке `computers_list.txt`.
